# ТЗ: автоматическая загрузка окладов и премий из Excel в 1С:ЗУП

**Организация:** Fansy
**Конфигурация:** 1С:Зарплата и управление персоналом 3.1 (по скриншоту журнала «Все начисления»)
**Источник данных:** Excel-файл «Выплаты Fansy 2026», лист **«Данные для расчета»**
**Дата:** 28.09.2026

---

## 1. Как сейчас

Каждый месяц бухгалтер вручную переносит данные из листа «Данные для расчета» в два документа 1С:

| Документ 1С | Пример (август 2026) | Комментарий | Откуда сумма в Excel |
|---|---|---|---|
| Начисление зарплаты и взносов | ФН00-000023 от 31.08.2026 — **701 498,33 ₽** | `Скауты_оклады` | **Оклад = K «Оклад» + J «Сдельный заработок»** (486 850,00 + 214 648,33) |
| Разовое начисление | ФН00-000047 от 31.08.2026 — **785 700,00 ₽** | `Скауты_премия_руб` | Колонка **L «Премия»** (785 700,00) |

Сверка по августу 2026: итоги строки «ИТОГО» (стр. 53) в точности совпадают с суммами документов.

Ручной перенос 37 строк долго занимает и приводит к ошибкам: в ФИО, в суммах, при пропуске человека. Новых людей (каждый месяц их несколько) бухгалтер тоже заводит в 1С вручную.

## 2. Что нужно сделать

Сделать обработку **«Загрузка начислений Fansy из Excel»** в расширении конфигурации. Типовую конфигурацию не снимать с поддержки.

Обработка читает лист «Данные для расчета» и делает три вещи:

1. **Заводит в 1С новых людей**, которых ещё нет: физлицо, сотрудник, приём на работу (п. 4.2).
2. Создаёт документ **«Начисление зарплаты и взносов»**: оклад, в который входит и сдельный заработок.
3. Создаёт документ **«Разовое начисление»**: премии.

**Загружаются все люди из таблицы**, независимо от должности: скауты, менеджеры, саппорт, контент-менеджеры и т. д. Комментарий «Скауты_…» — просто название пакета.

Документы должны получаться такими же, как те, что бухгалтер сейчас делает вручную, чтобы дальше работали штатный расчёт НДФЛ, взносов, выплата и отчётность.

## 3. Структура файла Excel

### 3.1 Лист «Данные для расчета»
- **A1**: заголовок «Выплаты Fansy»
- **A3 / B3**: «Период:» / дата первого числа месяца (например, `01.08.2026`). Отсюда берётся **месяц начисления**.
- **Строка 5**: заголовки колонок.
- **Строки 6…N**: люди.
- **Строка «ИТОГО»**: в колонке A стоит текст `ИТОГО` (в августе — стр. 53). Строка ниже — итог по USD.

| Кол. | Заголовок | Использование |
|---|---|---|
| A | Сотрудник | ФИО, **ключ поиска сотрудника**. ⚠️ Вместо пробелов бывают неразрывные (`\xa0`) и пробелы в конце строки |
| B | Должность | **Для новых сотрудников** — должность при приёме. Для остальных — в протокол |
| C | проект | Информационно (`Fancy`) |
| D | Способ оплаты | `СЗ - БВ`, `СЗ -БВ`, `4dev`, `крипта`. Информационно, начисление всем одинаково |
| E | НПД | Информационно |
| F | Валюта | `RUB` / `USD`. Формула VLOOKUP с листа Info |
| G / H | Часы / Минуты | Для почасовиков, информационно |
| I | Часовая ставка | Формула VLOOKUP с листа Info, информационно |
| J | Сдельный заработок | Формула `(G + H/60) × I`. **Прибавляется к окладу** |
| K | Оклад | **Оклад**. Сумма к начислению = **K + J** |
| L | Премия | **Загружается в «Разовое начисление»** |
| M | Прочие начисления | Сейчас везде 0. Если не 0, прибавлять к премии (или отдельный вид — по настройке) |
| N | Итого | `J + K + L`. Используется для контроля |
| O | Комментарии | Не загружать. Исключение: для новых сотрудников искать в тексте дату приёма (п. 4.2) |
| P, Q | 4дев, Отправить приглашение | Не загружать (email, кошельки и т. п.) |

### 3.2 Правила чтения
- Файл сохранён из Google Таблиц, в ячейках J, F, I, N стоят формулы. Читать **вычисленные значения**, а не текст формул.
- Строки с пустой колонкой A или с ошибкой `#N/A` в числовых колонках пропускать молча. В августе это строки 43–52.
- Чтение заканчивается на строке, где в колонке A стоит `ИТОГО`.
- Строки с валютой `USD` не загружать. Выводить их в протокол как требующие ручной обработки.
- Нулевые и пустые суммы не загружать:
  - оклад + сдельный = 0, а премия = 20 700 → человек попадает только в «Разовое начисление»;
  - оклад 8 600, премия 0 → только в «Начисление зарплаты».
- Суммы округлять до копеек. Округлять **сумму** K + J, а не каждое слагаемое: 0 + 48 995,8333 → 48 995,83. Итог по августу должен дать ровно 701 498,33.
- Другие листы (`Лист1`, `Info`, архивные «Данные для расчета (01.03)», «…01.02.24», «…январь 24») **не читать**. Лист выбирается в форме, по умолчанию — «Данные для расчета».

## 4. Сопоставление с 1С

### 4.1 Поиск существующих сотрудников
- Поиск по ФИО из колонки A: регистр не учитывается, «ё» = «е», неразрывные и повторные пробелы заменяются одним обычным, пробелы по краям убираются.
- Ищем сотрудников организации **Fansy**.
- В файле есть ФИО латиницей (`Muhammad Jawaid`), составные (`Варгас Уапая Патрик Стаброс`, `Мармолехос Диас Исаурис Эльвира`) и неполные (`Григорян Арпине`, `Ирдеменьтева Мария`). Для них нужен **регистр сведений «Сопоставление ФИО Excel → Сотрудник»**, который можно редактировать вручную. Сопоставление, выбранное один раз, запоминается и используется в следующие месяцы.
- Найдено несколько сотрудников с таким ФИО → строка не загружается, пользователь выбирает сотрудника вручную в предпросмотре.
- Сотрудник найден, но уволен до начала месяца → строка не загружается, попадает в протокол (п. 6). Повторный приём не делать автоматически, только предупредить.

### 4.2 Автоматическое заведение новых людей
Если человек из таблицы **не найден** ни по ФИО, ни в регистре сопоставления, обработка заводит его сама:

1. **Физическое лицо.** ФИО из колонки A разбирается на фамилию, имя и отчество:
   - первое слово — фамилия, второе — имя, остальное — отчество;
   - если слов больше трёх или ФИО латиницей, в предпросмотре отмечается «проверить ФИО», и разбор можно исправить вручную.

   Перед созданием проверить, нет ли физлица с таким ФИО без сотрудника в Fansy. Если есть, использовать его, а не создавать дубль.
2. **Сотрудник** организации Fansy, привязанный к этому физлицу.
3. **Документ «Приём на работу»**:
   - **дата приёма** — по умолчанию первое число месяца загрузки (ячейка B3). Если в колонке O есть фраза вида «дата приема: 05.08.25», брать дату оттуда. Дату можно изменить в предпросмотре;
   - **должность** — из колонки B. Ищется в справочнике «Должности» (по наименованию, без учёта регистра и лишних пробелов); если такой нет, создаётся;
   - **подразделение, график работы, вид занятости** («Основное место работы»), **вид договора** («Трудовой договор») — берутся из настроек обработки (п. 5.1);
   - **плановое начисление** — вид начисления «оклад» из настроек, размер = оклад из колонки K. Если K = 0, плановое начисление не назначать.
   - Документ проводится, иначе на сотрудника нельзя начислить зарплату.
4. После создания запись добавляется в регистр сопоставления ФИО.

Паспорт, СНИЛС, ИНН, адрес, дату рождения и пол обработка **не заполняет**, их в таблице нет. Созданные сотрудники выводятся в протоколе отдельным списком «Заведены автоматически — дозаполнить кадровые данные» со ссылками на карточки.

В форме есть флажок «Заводить новых сотрудников автоматически» (по умолчанию включён). Если его снять, новые люди только попадают в протокол.

### 4.3 Виды начислений
Виды выбираются в настройках обработки, не в коде:

| Колонка Excel | Документ | Вид начисления (**уточнить у бухгалтерии**, какой ставится вручную сейчас) |
|---|---|---|
| K «Оклад» + J «Сдельный заработок» | Начисление зарплаты и взносов | Один вид — «Оплата по окладу» или аналог. **Одна строка на человека**, сумма = K + J |
| L «Премия» (+ M «Прочие начисления») | Разовое начисление | «Премия разовая (сумма)» или аналог; код дохода НДФЛ 2000/2002 |

> Оклад в Excel уже посчитан (включая почасовую оплату). В документ «Начисление зарплаты» загружается **сумма из таблицы**, строки отмечаются как исправленные вручную (фиксированный результат). 1С не должна пересчитывать их по плановым начислениям и табелю, иначе суммы разойдутся с таблицей.
>
> Сотрудники, которых нет в плановом начислении за месяц, тоже должны попасть в документ со своей суммой. Если автозаполнение документа добавило людей, которых нет в таблице, их строки нужно удалить.

## 5. Функциональность обработки

### 5.1 Настройки (сохраняются)
- Организация (по умолчанию Fansy).
- Имя листа (по умолчанию «Данные для расчета»), номер строки заголовка (5), ячейка периода (B3).
- Соответствие колонок полям: по **тексту заголовка** («Сотрудник», «Должность», «Оклад», «Сдельный заработок», «Премия», «Прочие начисления», «Валюта», «Комментарии»), а не по букве колонки. В архивных листах колонки уже сдвигались: оклад был в H, премия в I.
- Виды начислений (п. 4.3).
- **Для новых сотрудников:** подразделение, график работы, вид занятости, вид договора, вид планового начисления.
- Комментарии документов: `Скауты_оклады`, `Скауты_премия_руб`.
- Флажок «Проводить документы начислений автоматически» (по умолчанию выключен).

### 5.2 Форма
1. Выбор Excel-файла (.xlsx) и листа.
2. Месяц начисления: берётся из ячейки B3, его можно изменить. Дата документа — последний день месяца.
3. Кнопка **«Прочитать файл»**: предпросмотр в таблице со столбцами:
   - «ФИО из файла», «Должность», «Сотрудник 1С», «Оклад (K+J)», «Премия (L+M)»;
   - «Статус»: ОК / **новый — будет заведён** / несколько совпадений / уволен / USD;
   - для новых — «Фамилия», «Имя», «Отчество» и «Дата приёма» (можно исправить).

   Сотрудника можно выбрать вручную прямо в таблице, и выбор сохранится в регистре сопоставления.
4. **Контроль итогов:** суммы предпросмотра по колонкам сравниваются со строкой «ИТОГО» из файла (оклад = K + J, премия = L + M). Если есть расхождение, показывается красное предупреждение с разницей.
5. Флажки «Заводить новых сотрудников», «Создать начисление зарплаты (оклад)», «Создать разовое начисление (премии)».
6. Кнопка **«Выполнить»**. Порядок: сначала приём новых сотрудников, потом документы начислений.

### 5.3 Создание документов
- **Начисление зарплаты и взносов**: за выбранный месяц, организация Fansy, комментарий `Скауты_оклады`. В табличную часть «Начисления» попадает **одна строка на человека** с видом «оклад» и фиксированной суммой K + J. После заполнения выполнить штатный пересчёт НДФЛ и взносов.
- **Разовое начисление**: вид начисления «премия», месяц начисления = выбранный месяц, дата = последний день месяца, комментарий `Скауты_премия_руб`, сумма L (+ M) на каждого человека. Выполнить штатный расчёт НДФЛ и взносов.
- Документы начислений **записываются, но не проводятся**, если в настройках не включено проведение. «Приём на работу» проводится всегда.
- **Защита от дублей:**
  - если за этот месяц уже есть документ организации Fansy с тем же комментарием:
    - если он не проведён, предложить перезаполнить его;
    - если проведён, выдать предупреждение. Перезаполнение — только после подтверждения пользователя и отмены проведения;
    - второй такой же документ молча не создавать;
  - при повторной загрузке того же файла новые сотрудники повторно не заводятся: их уже найдёт регистр сопоставления.

## 6. Протокол
После загрузки показать и сохранить (в журнал регистрации и в файл по кнопке):
- ссылки на созданные или изменённые документы и их суммы;
- **список заведённых сотрудников** (ФИО, должность, дата приёма, ссылка на «Приём на работу») с пометкой «дозаполнить кадровые данные»;
- число загруженных строк; итоги в сравнении со строкой «ИТОГО» из Excel;
- пропущенные строки с причинами: несколько совпадений, уволен, USD, некорректная сумма.

## 7. Права
- Запускать обработку могут роли «Расчётчик» и «Главный расчётчик», а также администратор.
- Для автоматического заведения сотрудников пользователю также нужны права кадровика (создание физлиц, сотрудников, документов «Приём на работу»). Если прав нет, новые люди только попадают в протокол.
- Регистр сопоставления ФИО редактирует только расчётчик и выше.

## 8. Критерии приёмки
1. Загружаем приложенный файл, лист «Данные для расчета», период 01.08.2026. Создаются два документа, которые **совпадают с ручными** ФН00-000023 и ФН00-000047 от 31.08.2026:
   - начисление зарплаты: **701 498,33 ₽** — одна строка «оклад» на человека (K + J);
   - разовое начисление: **785 700,00 ₽**;
   - состав людей тот же, НДФЛ и взносы совпадают с ручными документами.
2. **Проверка приёма новых.** Тест в копии базы: удаляем из сопоставления двух человек, например «Бабайцева Татьяна Игоревна» и «Григорян Арпине», и загружаем файл. Обработка:
   - заводит физлиц и сотрудников, проводит «Приём на работу» с должностью «Скаут» и датой 01.08.2026;
   - включает этих людей в оба документа;
   - выводит их в протокол.
3. Строка с «дата приема: 05.08.25» в комментарии даёт дату приёма из комментария.
4. Строки с `#N/A`, пустые строки и строка «ИТОГО» не загружаются.
5. Повторная загрузка того же месяца не создаёт ни дублей документов, ни дублей сотрудников.
6. Если колонки в Excel сдвинулись, а заголовки те же, загрузка работает без доработки.
7. После обновления типовой конфигурации ЗУП обработка работает (сделана в расширении).

## 9. Что передать разработчику
- Excel-файл «Выплаты Fansy 2026» (эталон структуры).
- Документы ФН00-000023 и ФН00-000047 за август 2026 (эталон результата).
- Название вида начисления для оклада и для премии.
- Для приёма новых: подразделение, график работы, вид договора по умолчанию.
- Версию конфигурации ЗУП и платформы.

## 10. Вопросы для уточнения (до начала работ)
1. Нужна ли загрузка по расписанию, например прямо из Google Таблицы по ссылке? Или хватит ручного запуска с выбором .xlsx?
2. Как поступать со строками в USD: пропускать или пересчитывать по курсу ЦБ?
3. Нужно ли автоматически увольнять людей, которые пропали из таблицы? (По умолчанию — нет, только список в протоколе.)
4. Нужно ли после проведения автоматически создавать ведомости на выплату?
