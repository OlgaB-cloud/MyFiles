# ТЗ: автоматическая загрузка окладов и премий скаутов из Excel в 1С:ЗУП

**Организация:** Fansy
**Конфигурация:** 1С:Зарплата и управление персоналом 3.1 (по скриншоту журнала «Все начисления»)
**Источник данных:** Excel-файл «Выплаты Fansy 2026», лист **«Данные для расчета»**
**Дата:** 28.09.2026

---

## 1. Как сейчас

Каждый месяц бухгалтер вручную переносит данные из листа «Данные для расчета» в два документа 1С:

| Документ 1С | Пример (август 2026) | Комментарий | Откуда сумма в Excel |
|---|---|---|---|
| Начисление зарплаты и взносов | ФН00-000023 от 31.08.2026 — **701 498,33 ₽** | `Скауты_оклады` | Колонка **K «Оклад»** (486 850,00) + колонка **J «Сдельный заработок»** (214 648,33) |
| Разовое начисление | ФН00-000047 от 31.08.2026 — **785 700,00 ₽** | `Скауты_премия_руб` | Колонка **L «Премия»** (785 700,00) |

> Сверка по августу 2026: итоги строки «ИТОГО» (стр. 53) в точности совпадают с суммами документов.
> Значит, в 1С загружается **весь лист** «Данные для расчета» (37 человек: скауты, аккаунт-менеджеры, саппорт, контент-менеджеры и т. д.), а не только строки с должностью «Скаут».
> Комментарий «Скауты_…» — это просто название пакета.

Ручной перенос 37 строк долго занимает и приводит к ошибкам: в ФИО, в суммах, при пропуске сотрудника.

## 2. Что нужно сделать

Сделать внешнюю обработку (или встроить её в расширение конфигурации) **«Загрузка начислений Fansy из Excel»**. Она читает лист «Данные для расчета» и сама создаёт или перезаполняет документы:

1. **Начисление зарплаты и взносов**: оклад + сдельный (почасовой) заработок;
2. **Разовое начисление**: премии.

Документы должны получаться такими же, как те, что бухгалтер сейчас делает вручную, чтобы дальше работали штатный расчёт НДФЛ, взносов, выплата и отчётность.

Доработки делать через **расширение конфигурации**. Типовую конфигурацию не снимать с поддержки.

## 3. Структура файла Excel

### 3.1 Лист «Данные для расчета»
- **A1**: заголовок «Выплаты Fansy»
- **A3 / B3**: «Период:» / дата первого числа месяца (например, `01.08.2026`). Отсюда берётся **месяц начисления**.
- **Строка 5**: заголовки колонок.
- **Строки 6…N**: сотрудники.
- **Строка «ИТОГО»**: в колонке A стоит текст `ИТОГО` (в августе — стр. 53). Строка ниже — итог по USD.

| Кол. | Заголовок | Использование |
|---|---|---|
| A | Сотрудник | ФИО, **ключ поиска сотрудника**. ⚠️ Вместо пробелов бывают неразрывные (`\xa0`) и пробелы в конце строки |
| B | Должность | Только информационно (в протокол) |
| C | проект | Информационно (`Fancy`) |
| D | Способ оплаты | `СЗ - БВ`, `СЗ -БВ`, `4dev`, `крипта`. Информационно, см. вопрос 4 в п. 10 |
| E | НПД | Информационно |
| F | Валюта | `RUB` / `USD`. Формула VLOOKUP с листа Info |
| G / H | Часы / Минуты | Для сдельщиков |
| I | Часовая ставка | Формула VLOOKUP с листа Info |
| J | Сдельный заработок | Формула `(G + H/60) × I`. **Загружается в «Начисление зарплаты»** |
| K | Оклад | **Загружается в «Начисление зарплаты»** |
| L | Премия | **Загружается в «Разовое начисление»** |
| M | Прочие начисления | Сейчас везде 0. Предусмотреть загрузку отдельным видом начисления (по настройке) |
| N | Итого | `J + K + L`. Используется для контроля |
| O, P, Q | Комментарии, 4дев, Отправить приглашение | Не загружать (email, кошельки и т. п.) |

### 3.2 Правила чтения
- Файл сохранён из Google Таблиц, в ячейках J, F, I, N стоят формулы. Читать **вычисленные значения**, а не текст формул.
- Строки с пустой колонкой A или с ошибкой `#N/A` в числовых колонках пропускать молча. В августе это строки 43–52.
- Чтение заканчивается на строке, где в колонке A стоит `ИТОГО`.
- Строки с валютой `USD` не загружать. Выводить их в протокол как требующие ручной обработки.
- Нулевые и пустые суммы не загружать. Сотрудник с окладом 0 и премией 20 700 попадает только в «Разовое начисление».
- Суммы округлять до копеек. Сдельный заработок бывает дробным: 48 995,8333 → 48 995,83. Правило округления сверить с ручным документом (п. 8).
- Другие листы (`Лист1`, `Info`, архивные «Данные для расчета (01.03)», «…01.02.24», «…январь 24») **не читать**. Лист выбирается в форме, по умолчанию — «Данные для расчета».

## 4. Сопоставление с 1С

### 4.1 Сотрудники
- Поиск по ФИО из колонки A: регистр не учитывается, «ё» = «е», неразрывные и повторные пробелы заменяются одним обычным, пробелы по краям убираются.
- Ищем только сотрудников организации **Fansy**, которые работают в выбранном месяце.
- В файле есть ФИО латиницей (`Muhammad Jawaid`) и составные (`Варгас Уапая Патрик Стаброс`, `Мармолехос Диас Исаурис Эльвира`), а также неполные (`Григорян Арпине`, `Ирдеменьтева Мария`). Для таких случаев нужен **регистр сведений «Сопоставление ФИО Excel → Сотрудник»**, который можно редактировать вручную. Сопоставление, выбранное один раз, запоминается и используется в следующие месяцы.
- Если сотрудник не найден, найден несколько раз или уволен до начала месяца, строка не загружается. Она попадает в протокол ошибок (п. 6), а обработка продолжает работу.
- Каждый месяц в файле появляются новые люди (пометка «НОВЫЙ СКАУТ»). Если такого сотрудника ещё не приняли в 1С, выводить отдельный список «Не приняты в 1С».

### 4.2 Виды начислений
Виды выбираются в настройках обработки, не в коде:

| Колонка Excel | Документ | Вид начисления (**уточнить у бухгалтерии**, какой ставится вручную сейчас) |
|---|---|---|
| K «Оклад» | Начисление зарплаты и взносов | «Оплата по окладу» или аналог |
| J «Сдельный заработок» | Начисление зарплаты и взносов | «Оплата по часовому тарифу» / отдельный вид «Сдельная оплата» |
| L «Премия» | Разовое начисление | «Премия разовая (сумма)» или аналог; код дохода НДФЛ 2000/2002 |
| M «Прочие начисления» | Разовое начисление (отдельный документ) | По настройке; если вид не задан, не загружать |

> Оклад и сдельный заработок в Excel уже посчитаны. В документ «Начисление зарплаты» загружается **сумма из таблицы**, строки отмечаются как исправленные вручную (фиксированный результат). 1С не должна пересчитывать их по плановым начислениям и табелю, иначе суммы разойдутся с таблицей.

## 5. Функциональность обработки

### 5.1 Настройки (сохраняются)
- Организация (по умолчанию Fansy).
- Имя листа (по умолчанию «Данные для расчета»), номер строки заголовка (5), ячейка периода (B3).
- Соответствие колонок полям: по **тексту заголовка** («Сотрудник», «Оклад», «Премия», «Сдельный заработок», «Прочие начисления», «Валюта»), а не по букве колонки. В архивных листах колонки уже сдвигались: оклад был в H, премия в I.
- Виды начислений (п. 4.2).
- Комментарии документов: `Скауты_оклады`, `Скауты_премия_руб`.
- Флажок «Проводить документы автоматически» (по умолчанию выключен).

### 5.2 Форма
1. Выбор Excel-файла (.xlsx) и листа.
2. Месяц начисления: берётся из ячейки B3, его можно изменить. Дата документа — последний день месяца.
3. Кнопка **«Прочитать файл»**: предпросмотр в таблице со столбцами «ФИО из файла», «Должность», «Сотрудник 1С», «Оклад», «Сдельный», «Премия», «Прочие», «Статус» (ОК / не найден / дубль / уволен / USD). Сотрудника можно выбрать вручную прямо в таблице, и выбор сохранится в регистре сопоставления.
4. **Контроль итогов:** суммы предпросмотра по колонкам сравниваются со строкой «ИТОГО» из файла. Если есть расхождение, показывается красное предупреждение с разницей.
5. Флажки «Создать начисление зарплаты (оклад + сдельный)» и «Создать разовое начисление (премии)».
6. Кнопка **«Создать документы»**.

### 5.3 Создание документов
- **Начисление зарплаты и взносов**: за выбранный месяц, организация Fansy, комментарий `Скауты_оклады`. В табличную часть «Начисления» попадает по строке на каждый вид начисления у каждого сотрудника (оклад и сдельный — отдельными строками) с фиксированной суммой из таблицы. После заполнения выполнить штатный пересчёт НДФЛ и взносов.
- **Разовое начисление**: вид начисления «премия», месяц начисления = выбранный месяц, дата = последний день месяца, комментарий `Скауты_премия_руб`, сумма из колонки L на каждого сотрудника. Выполнить штатный расчёт НДФЛ и взносов.
- Документы **записываются, но не проводятся**, если в настройках не включено проведение.
- **Защита от дублей**: если за этот месяц уже есть документ организации Fansy с тем же комментарием:
  - если он не проведён, предложить перезаполнить его;
  - если проведён, выдать предупреждение. Перезаполнение — только после подтверждения пользователя и отмены проведения.
  - Второй такой же документ молча не создавать.

## 6. Протокол
После загрузки показать и сохранить (в журнал регистрации и в файл по кнопке):
- ссылки на созданные или изменённые документы и их суммы;
- число загруженных строк; итоги в сравнении со строкой «ИТОГО» из Excel;
- пропущенные строки с причинами: не найден сотрудник, не принят в 1С, уволен, USD, некорректная сумма.

## 7. Права
- Запускать обработку могут роли «Расчётчик» и «Главный расчётчик», а также администратор.
- Регистр сопоставления ФИО редактирует только расчётчик и выше.

## 8. Критерии приёмки
1. Загружаем приложенный файл, лист «Данные для расчета», период 01.08.2026. Создаются два документа, которые **совпадают с ручными** ФН00-000023 и ФН00-000047 от 31.08.2026:
   - начисление зарплаты: **701 498,33 ₽** (486 850,00 оклад + 214 648,33 сдельный), тот же состав сотрудников;
   - разовое начисление: **785 700,00 ₽**, тот же состав сотрудников;
   - НДФЛ и взносы совпадают с ручными документами.
2. Сотрудники из строк 6–42 сопоставлены, включая ФИО с неразрывными пробелами. Нераспознанные строки — в протоколе, остальные загружены.
3. Строки с `#N/A`, пустые строки и строка «ИТОГО» не загружаются.
4. Повторная загрузка того же месяца не создаёт дублей (п. 5.3).
5. Если колонки в Excel сдвинулись, а заголовки те же, загрузка работает без доработки.
6. После обновления типовой конфигурации ЗУП обработка работает (сделана в расширении).

## 9. Что передать разработчику

- Названия видов начислений, которые сейчас ставятся для оклада, сдельного и премии.
- Версию конфигурации ЗУП и платформы.

## 10. Вопросы для уточнения (до начала работ)
1. Загружать весь лист (как сейчас, 37 человек) или только строки с должностью «Скаут»? По суммам августа в 1С сейчас попадает весь лист.
2. Нужна ли загрузка по расписанию, например прямо из Google Таблицы по ссылке? Или хватит ручного запуска с выбором .xlsx?
3. Как поступать со строками в USD: пропускать или пересчитывать по курсу ЦБ?
4. В колонке «Способ оплаты» указаны `СЗ - БВ` (самозанятые), `4dev`, `крипта`. Самозанятые по закону не должны проходить через «Начисление зарплаты» с НДФЛ и взносами. Нужно подтвердить, что эти люди действительно оформлены сотрудниками по трудовому договору. Или их часть надо загружать другим документом («Договор (работы, услуги)» / «Акт») либо не загружать вовсе?
5. Нужно ли после проведения автоматически создавать ведомости на выплату?
