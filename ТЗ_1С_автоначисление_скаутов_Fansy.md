## 2. Что нужно сделать

Сделать обработку **«Загрузка начислений Fansy из Excel»** в расширении конфигурации. Типовую конфигурацию не снимать с поддержки.

Обработка **сама забирает свежую таблицу из Telegram-чата** (п. 3.1), читает лист «Данные для расчета» и по порядку:

1. **Получает файл** из Telegram-чата https://t.me/+MkKkPuP3QsUyYWZi.
2. **Заводит в 1С новых людей**, которых ещё нет: физлицо, сотрудник, проведённый «Приём на работу» (п. 4.2).
3. Создаёт **«Начисление зарплаты и взносов»**: по каждому человеку **оклад + сдельный** одной строкой, вид «Оплата по окладу УУ».
4. Создаёт **«Разовое начисление»**: премии.
5. Создаёт **«Ведомость на счета»**: выплата людям со способом оплаты `4dev`.

**Начисления делаются всем людям из таблицы**, независимо от должности и способа оплаты. Ведомость — только для `4dev`.

## 3. Источник и структура файла Excel

- Сервер 1С должен иметь доступ к `api.telegram.org` по HTTPS (при необходимости — через прокси, адрес задаётся в настройках).

**Какой файл брать**
- Обработка получает новые сообщения чата (`getUpdates`; если сервер 1С доступен из интернета — через webhook) и выбирает сообщения с **документом .xlsx**.
- Подходит файл, у которого:
  - имя соответствует маске из настроек (по умолчанию `*Fansy*.xlsx`);
  - есть лист «Данные для расчета» со строкой заголовков, как в п. 3.2.
- Если за период прислано несколько файлов, берётся **последний по времени**: он считается исправленной версией.
- Скачивание: `getFile` → загрузка по `file_path`. Ограничение Bot API — 20 МБ, текущий файл весит намного меньше.
- Месяц начисления определяется по ячейке B3 **внутри файла**, а не по дате сообщения.

**Учёт обработанных файлов**
- Нужен **регистр сведений «Загруженные файлы Telegram»**:
  - поля: chat_id, message_id, file_unique_id, имя файла, отправитель, дата сообщения, период из B3, статус, ссылки на созданные документы;
  - один и тот же файл (по `file_unique_id`) второй раз не обрабатывается.
- Если пришёл **новый файл за тот же месяц**, документы этого месяца **перезаполняются** по правилам п. 5.4: непроведённые — автоматически, проведённые — только после подтверждения пользователя.

**Когда забирать файл**
- **Регламентное задание** «Загрузка начислений Fansy из Telegram»: по умолчанию каждые 30 минут, расписание меняется в настройках. Задание забирает новый файл и создаёт документы **без проведения**.
- **Кнопка в форме** «Загрузить из Telegram»: берёт последний подходящий файл из чата и открывает предпросмотр (п. 6.2).
- Остаётся и **ручной выбор файла** с диска на случай, если Telegram недоступен.

**Ответ в чат** (включается в настройках)
- После обработки бот отвечает **на сообщение с файлом** коротким итогом:

### 3.2 Лист «Данные для расчета»
- **A1**: заголовок «Выплаты Fansy»
- **A3 / B3**: «Период:» / дата первого числа месяца (например, `01.08.2026`). Отсюда берётся **месяц начисления**.
- **Строка 5**: заголовки колонок.
- **Строки 6…N**: люди.
- **Строка «ИТОГО»**: в колонке A стоит текст `ИТОГО` (в августе — стр. 53). Строка ниже — итог по USD.

| Кол. | Заголовок | Использование |
|---|---|---|
| A | Сотрудник | ФИО, **ключ поиска сотрудника**. ⚠️ Вместо пробелов бывают неразрывные (`\xa0`) и пробелы в конце строки |
| B | Должность | Для новых: по ней выбираются должность и подразделение в 1С (п. 4.2) |
| C | проект | Информационно (`Fancy`) |
| D | Способ оплаты | `4dev` → **включать в ведомость на счета**. `СЗ - БВ`, `СЗ -БВ`, `крипта` → только начисления, без ведомости |
| E | НПД | Информационно |
| F | Валюта | `RUB` / `USD`. Формула VLOOKUP с листа Info |
| G / H / I | Часы / Минуты / Часовая ставка | Информационно |
| J | Сдельный заработок | Формула `(G + H/60) × I`. **Прибавляется к окладу** |
| K | Оклад | Сумма к начислению = **K + J** |
| L | Премия | **Разовое начисление** |
| M | Прочие начисления | Сейчас везде 0. Если не 0 — прибавлять к премии |
| N | Итого | `J + K + L`. Контроль. **Сумма ведомости** по `4dev` |
| O | Комментарии | Не загружать. Исключение: для новых сотрудников искать в тексте дату приёма (п. 4.2) |
| P, Q | 4дев, Отправить приглашение | Не загружать (email, кошельки и т. п.) |

### 3.3 Правила чтения
- Файл сохранён из Google Таблиц, в ячейках J, F, I, N стоят формулы. Читать **вычисленные значения**, а не текст формул.
- Строки с пустой колонкой A или с ошибкой `#N/A` в числовых колонках пропускать молча. В августе это строки 43–52.
- Чтение заканчивается на строке, где в колонке A стоит `ИТОГО`.
- Строки с валютой `USD` не загружать. Выводить их в протокол.
- Способ оплаты сравнивать без учёта регистра и пробелов: `СЗ - БВ` = `СЗ -БВ`, `4dev` = `4DEV`.
- Нулевые суммы не загружать:
  - оклад + сдельный = 0 → человека нет в «Начислении зарплаты»;
  - премия = 0 → нет в «Разовом начислении».
- Округлять до копеек **сумму** K + J, а не слагаемые. Итог по августу должен дать ровно 701 498,33.
- Другие листы (`Лист1`, `Info`, архивные) **не читать**. Лист выбирается в форме, по умолчанию — «Данные для расчета».

### 4.2 Автоматическое заведение новых людей
Если человек **не найден**, обработка заводит его сама.

**1. Физическое лицо.** ФИО разбирается так:
- первое слово — фамилия, второе — имя, остальное — отчество;
- если слов больше трёх или ФИО латиницей — пометка «проверить ФИО», разбор можно исправить вручную.

Перед созданием проверить, нет ли физлица с таким ФИО. Если есть, использовать его.

**2. Сотрудник** организации Fansy.

**3. Документ «Приём на работу»**, проводится. Реквизиты берутся из **таблицы соответствия «Должность в Excel → кадровые данные»** в настройках. Для скаутов (колонка B = «Скаут») значения такие:

| Реквизит | Значение |
|---|---|
| Подразделение | **Скаутинг** |
| Должность | **Скаут /Fansy_Скауты/** |
| Количество ставок | **1** |
| График работы | **Внешнее совместительство** |
| Вид занятости | **Внешнее совместительство** |
| Отразить в трудовой книжке | **Нет** (флажок снят) |
| Ежегодный отпуск | 28 дн. (по умолчанию) |
| Плановое начисление | **Оплата по окладу УУ**, показатель **Оклад УУ** — **не заполнять** (размер оклада каждый месяц разный, сумма приходит из таблицы) |
| Дата приёма | Первое число месяца загрузки (B3). Если в колонке O есть фраза вида «дата приема: 05.08.25» — брать дату оттуда. Можно исправить в предпросмотре |

Для других должностей (аккаунт-менеджер, саппорт, контент-менеджер и т. д.) бухгалтер заполняет такие же строки в таблице соответствия. Если у нового человека должность не найдена в таблице, он **не заводится**. Он попадает в протокол со статусом «нет настройки для должности».

**4.** После создания запись добавляется в регистр сопоставления ФИО.

Паспорт, СНИЛС, ИНН, дата рождения и пол в таблице отсутствуют, поэтому не заполняются. Созданные сотрудники выводятся в протоколе списком «Заведены автоматически — дозаполнить кадровые данные» со ссылками на карточки.

## 5. Документы

### 5.1 Начисление зарплаты и взносов
- Месяц — из B3, дата — последний день месяца, организация Fansy, комментарий `Скауты_оклады`.
- **Одна строка на человека:** вид начисления **«Оплата по окладу УУ»**, результат = K + J (фиксированная сумма, отметка «исправлено вручную»). 1С не должна пересчитывать сумму по показателю «Оклад УУ» и табелю.
- Если автозаполнение документа добавило людей, которых нет в таблице, их строки удалить.
- **НДФЛ не рассчитывать и не удерживать:** вкладка НДФЛ в документе остаётся пустой. Взносы — как в ручных документах (сверить с эталоном ФН00-000023).

### 5.2 Разовое начисление
Реквизиты — как в ручных документах (эталон: ФН00-000041 за июль 2026, ФН00-000047 за август 2026):

| Реквизит | Значение |
|---|---|
| Месяц | Месяц из B3 (например, «Август 2026») |
| Дата | Последний день месяца (31.08.2026) |
| Организация | Fansy |
| Подразделение | **Не заполнять** (пусто) |
| Начисление | **Премия за месяц суммой УУ** |
| Дата начала / Дата окончания | Первый / последний день месяца (01.08.2026 – 31.08.2026) |
| Способ отражения | **Отражение Премия** |
| Учитывать как | Не менять (значение по умолчанию: «Расчеты по оплате труда») |
| Комментарий | `Скауты_премия_руб` |

- Сумма = L (+ M) на каждого человека, одна строка на человека.
- **НДФЛ не рассчитывать и не удерживать.** Взносы — как в ручных документах (сверить с эталоном ФН00-000047).

### 5.3 Ведомость на счета (только `4dev`)
- Документ **«Ведомость на счета»**, организация Fansy.
- **Вид выплаты:** «Зарплата за месяц».
- **Месяц:** месяц из B3.
- **Дата:** **15-е число следующего месяца** (для августа — 15.09.2026). Число задаётся в настройках.
- **Комментарий:** `4DEV`. **Ответственный:** текущий пользователь.
- **Состав:** только люди, у которых в колонке D указано `4dev`. Остальные (`СЗ - БВ`, `крипта`) в ведомость не попадают.
- Ведомость создаётся **после проведения** обоих документов начислений.
- **НДФЛ не учитывается:** к выплате = **всё начисленное** без удержания НДФЛ, то есть сумма колонки N «Итого» по человеку. Колонка «НДФЛ к перечислению» в ведомости — 0.
- Заполнение: штатная команда «Заполнить» по сотрудникам `4dev`, строки остальных удаляются. Если штатное заполнение даёт сумму, отличную от N (например, из-за остатков прошлых месяцев), сумма к выплате **фиксируется равной N**, а человек попадает в протокол.
- **Контроль суммы:** итог ведомости = сумма колонки N по строкам `4dev` (август: **794 302,50 ₽**, совпадает с ФН00-000057).
- Если начисления не проведены (флажок проведения выключен), ведомость не создаётся. В протоколе пишется, что сначала нужно провести начисления и запустить шаг «Ведомость» повторно.

### 5.4 Защита от дублей
- Документ за месяц ищется по организации, месяцу и комментарию (`Скауты_оклады` / `Скауты_премия_руб` / `4DEV`):
  - если найден непроведённый — предложить перезаполнить его;
  - если найден проведённый — предупредить. Перезаполнить только после подтверждения пользователя и отмены проведения;
  - второй такой же документ молча не создавать.
- При повторной загрузке новые сотрудники повторно не заводятся (их находит регистр сопоставления).

### 6.2 Порядок работы
1. Кнопка **«Загрузить из Telegram»**: берётся последний подходящий файл из чата. Можно выбрать файл и с диска. Лист — «Данные для расчета», месяц подставляется из B3. В форме видно, из какого сообщения взят файл: отправитель, дата, имя файла.
